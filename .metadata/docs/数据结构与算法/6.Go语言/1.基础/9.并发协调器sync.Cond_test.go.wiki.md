- sync.Cond 是 golang 标准库提供的并发协调器，用于实现在指定条件下阻塞和唤醒协程的操作.

- 总结

  - cond.Wait() 必须在 cond.L.Lock() 和 cond.L.Unlock() 之间调用，以确保在等待期间锁被正确释放和重新获取。
  - 使用 for 循环而不是 if 来检查条件，以防止虚假唤醒（spurious wakeups）。
  - cond.Signal() 和 cond.Broadcast() 必须在 cond.L.Lock() 和 cond.L.Unlock() 之后调用，以确保在通知时锁被正确持有。

- 用法

`sync.Cond` 是 Go 语言标准库中的一个同步原语，用于协调多个 goroutine 之间的等待和通知。它通常与一个共享资源或条件相关联，允许多个 goroutine 在某个条件满足时被唤醒。

#### 用法

`sync.Cond` 的使用涉及以下几个步骤：

1. **创建 `sync.Cond` 实例**：
   ```go
   var mu sync.Mutex
   cond := sync.NewCond(&mu)
   ```
   这里需要传入一个 `sync.Locker` 接口的实现，通常是一个 `sync.Mutex` 或 `sync.RWMutex`。

2. **等待条件**：
   ```go
   cond.L.Lock()
   for !condition {
       cond.Wait()
   }
   // 处理条件满足后的逻辑
   cond.L.Unlock()
   ```
   `cond.Wait()` 会自动释放锁并阻塞当前 goroutine，直到被其他 goroutine 唤醒。当被唤醒时，它会重新获取锁。

3. **通知等待的 goroutine**：
   ```go
   cond.L.Lock()
   // 修改共享资源或条件
   cond.Signal()  // 唤醒一个等待的 goroutine
   // 或者
   cond.Broadcast()  // 唤醒所有等待的 goroutine
   cond.L.Unlock()
   ```
   `cond.Signal()` 用于唤醒一个等待的 goroutine，而 `cond.Broadcast()` 用于唤醒所有等待的 goroutine。

#### 应用场景

`sync.Cond` 适用于以下场景：

1. **生产者-消费者问题**：
   多个生产者 goroutine 和多个消费者 goroutine 共享一个缓冲区。当缓冲区满时，生产者需要等待；当缓冲区空时，消费者需要等待。

2. **事件通知**：
   多个 goroutine 等待某个事件的发生。当事件发生时，所有等待的 goroutine 需要被唤醒。

3. **资源池管理**：
   多个 goroutine 等待获取资源。当资源可用时，等待的 goroutine 被唤醒并获取资源。

#### 示例

以下是一个简单的生产者-消费者示例：

```go
package main

import (
    "fmt"
    "sync"
    "time"
)

var (
    mu    sync.Mutex
    cond  *sync.Cond
    queue []int
)

func producer() {
    for i := 0; i < 10; i++ {
        mu.Lock()
        queue = append(queue, i)
        fmt.Println("Produced:", i)
        mu.Unlock()
        cond.Signal()  // 唤醒一个消费者
        time.Sleep(100 * time.Millisecond)
    }
}

func consumer() {
    for {
        mu.Lock()
        for len(queue) == 0 {
            cond.Wait()  // 等待生产者通知
        }
        item := queue[0]
        queue = queue[1:]
        fmt.Println("Consumed:", item)
        mu.Unlock()
    }
}

func main() {
    cond = sync.NewCond(&mu)

    go consumer()
    go consumer()
    producer()
}
```

在这个示例中，`producer` 函数生产数据并放入队列，然后通过 `cond.Signal()` 通知等待的消费者。`consumer` 函数在队列为空时通过 `cond.Wait()` 等待生产者的通知，并在被唤醒后消费队列中的数据。

#### 注意事项

- `cond.Wait()` 必须在 `cond.L.Lock()` 和 `cond.L.Unlock()` 之间调用，以确保在等待期间锁被正确释放和重新获取。
- 使用 `for` 循环而不是 `if` 来检查条件，以防止虚假唤醒（spurious wakeups）。
- `cond.Signal()` 和 `cond.Broadcast()` 必须在 `cond.L.Lock()` 和 `cond.L.Unlock()` 之间调用，以确保在通知时锁被正确持有。

通过合理使用 `sync.Cond`，可以有效地协调多个 goroutine 之间的等待和通知，从而实现复杂的并发控制逻辑。

### 示例2 事件通知


`EventBus` 是一个常见的编程模式，用于在不同组件之间发布和订阅事件。基于 `sync.Cond` 实现一个简单的 `EventBus` 可以有效地协调多个 goroutine 之间的通信。

以下是一个基于 `sync.Cond` 的简单 `EventBus` 实现：

```go
package main

import (
    "fmt"
    "sync"
    "time"
)

type Event struct {
    Type string
    Data interface{}
}

type EventBus struct {
    mu      sync.Mutex
    cond    *sync.Cond
    events  []Event
    waiting int
}

func NewEventBus() *EventBus {
    eb := &EventBus{}
    eb.cond = sync.NewCond(&eb.mu)
    return eb
}

func (eb *EventBus) Publish(event Event) {
    eb.mu.Lock()
    eb.events = append(eb.events, event)
    eb.mu.Unlock()
    eb.cond.Broadcast() // 唤醒所有等待的订阅者
}

func (eb *EventBus) Subscribe(eventType string, handler func(Event)) {
    go func() {
        for {
            eb.mu.Lock()
            for len(eb.events) == 0 || eb.events[0].Type != eventType {
                eb.waiting++
                eb.cond.Wait()
                eb.waiting--
            }
            event := eb.events[0]
            eb.events = eb.events[1:]
            eb.mu.Unlock()
            handler(event)
        }
    }()
}

func main() {
    eb := NewEventBus()

    eb.Subscribe("type1", func(event Event) {
        fmt.Printf("Handler 1: %v\n", event)
    })

    eb.Subscribe("type2", func(event Event) {
        fmt.Printf("Handler 2: %v\n", event)
    })

    time.Sleep(1 * time.Second)

    eb.Publish(Event{Type: "type1", Data: "Hello, Type1!"})
    eb.Publish(Event{Type: "type2", Data: "Hello, Type2!"})

    time.Sleep(1 * time.Second)
}
```

#### 实现说明

1. **Event 结构体**：定义事件的类型和数据。
2. **EventBus 结构体**：包含一个互斥锁 `mu`、一个条件变量 `cond`、一个事件队列 `events` 和一个等待计数器 `waiting`。
3. **NewEventBus 函数**：创建并返回一个新的 `EventBus` 实例。
4. **Publish 方法**：发布一个事件，将事件添加到事件队列中，并调用 `cond.Broadcast()` 唤醒所有等待的订阅者。
5. **Subscribe 方法**：订阅特定类型的事件，并在一个单独的 goroutine 中处理事件。订阅者会在事件队列为空或没有匹配的事件类型时进入等待状态。

#### 使用场景

这个简单的 `EventBus` 实现可以用于以下场景：

- 多个组件之间的事件通知和处理。
- 异步任务的发布和订阅。
- 实现观察者模式。

#### 注意事项

- 在 `Subscribe` 方法中，使用 `for` 循环而不是 `if` 来检查条件，以防止虚假唤醒。
- `Publish` 方法中使用 `cond.Broadcast()` 而不是 `cond.Signal()`，因为可能有多个订阅者在等待同一类型的事件。
- 在 `Subscribe` 方法中，订阅者会在一个无限循环中处理事件，因此需要确保在处理事件时不会发生死锁或资源泄漏。

通过合理使用 `sync.Cond`，可以实现一个简单而高效的 `EventBus`，用于协调多个 goroutine 之间的通信。

### 示例3 资源池

`sync.Cond` 可以用于实现资源池管理，特别是在需要动态分配和回收资源的场景中。以下是一个简单的资源池管理示例，展示了如何使用 `sync.Cond` 来协调多个 goroutine 对资源池的访问。

```go
package main

import (
    "fmt"
    "sync"
    "time"
)

type Resource struct {
    ID int
}

type ResourcePool struct {
    mu        sync.Mutex
    cond      *sync.Cond
    resources []*Resource
    maxSize   int
}

func NewResourcePool(maxSize int) *ResourcePool {
    rp := &ResourcePool{
        maxSize: maxSize,
    }
    rp.cond = sync.NewCond(&rp.mu)
    return rp
}

func (rp *ResourcePool) Get() *Resource {
    rp.mu.Lock()
    defer rp.mu.Unlock()

    for len(rp.resources) == 0 {
        rp.cond.Wait()
    }

    resource := rp.resources[0]
    rp.resources = rp.resources[1:]
    return resource
}

func (rp *ResourcePool) Put(resource *Resource) {
    rp.mu.Lock()
    defer rp.mu.Unlock()

    if len(rp.resources) < rp.maxSize {
        rp.resources = append(rp.resources, resource)
        rp.cond.Signal()
    }
}

func main() {
    rp := NewResourcePool(3)

    // 初始化资源池
    for i := 0; i < 3; i++ {
        rp.Put(&Resource{ID: i})
    }

    var wg sync.WaitGroup

    // 模拟多个 goroutine 获取和释放资源
    for i := 0; i < 5; i++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            resource := rp.Get()
            fmt.Printf("Goroutine %d acquired resource %d\n", id, resource.ID)
            time.Sleep(time.Duration(id+1) * 100 * time.Millisecond)
            rp.Put(resource)
            fmt.Printf("Goroutine %d released resource %d\n", id, resource.ID)
        }(i)
    }

    wg.Wait()
}
```

#### 实现说明

1. **Resource 结构体**：表示资源，包含一个唯一的 ID。
2. **ResourcePool 结构体**：包含一个互斥锁 `mu`、一个条件变量 `cond`、一个资源列表 `resources` 和一个最大资源数 `maxSize`。
3. **NewResourcePool 函数**：创建并返回一个新的 `ResourcePool` 实例。
4. **Get 方法**：从资源池中获取一个资源。如果资源池为空，则等待直到有资源可用。
5. **Put 方法**：将一个资源放回资源池。如果资源池未满，则将资源添加到资源池中，并通知等待的 goroutine。

#### 使用场景

这个简单的资源池管理示例可以用于以下场景：

- 数据库连接池管理。
- 网络连接池管理。
- 对象池管理，用于减少对象创建和销毁的开销。

#### 注意事项

- 在 `Get` 方法中，使用 `for` 循环而不是 `if` 来检查条件，以防止虚假唤醒。
- `Put` 方法中使用 `cond.Signal()` 而不是 `cond.Broadcast()`，因为通常只需要唤醒一个等待的 goroutine。
- 在 `Put` 方法中，确保资源池未满时才添加资源，避免资源池溢出。

通过合理使用 `sync.Cond`，可以实现一个简单而高效的资源池管理机制，用于协调多个 goroutine 对资源的访问。
