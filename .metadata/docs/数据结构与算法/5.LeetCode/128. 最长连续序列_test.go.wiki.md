```
	public static int longestConsecutive(int[] nums) {
		HashMap<Integer, Integer> map = new HashMap<>();
		int len = 0;
		for (int num : nums) {
			if (!map.containsKey(num)) {
				map.put(num, 1);
				int preLen = map.containsKey(num - 1) ? map.get(num - 1) : 0;
				int posLen = map.containsKey(num + 1) ? map.get(num + 1) : 0;
				int all = preLen + posLen + 1;
				map.put(num - preLen, all);
				map.put(num + posLen, all);
				len = Math.max(len, all);
			}
		}
		return len;
	}
```


## 问答



**问：切片的插入操作时间复杂度多少？**

答：在Go语言中，切片（slice）的插入操作时间复杂度取决于插入的位置和切片的长度。具体来说，插入操作通常涉及到以下几个步骤：

1. **找到插入位置**：这一步通常是O(1)时间复杂度，因为你可以直接通过索引访问到插入位置。

2. **移动元素**：为了给新元素腾出空间，你需要将插入位置及其之后的所有元素向后移动一位。如果切片的长度为n，那么这一步的时间复杂度是O(n)，因为你可能需要移动切片中的大部分元素。

3. **插入新元素**：这一步是O(1)时间复杂度，因为你只需要在指定位置赋值即可。

综合以上步骤，如果你在切片的末尾插入元素（即追加操作），那么时间复杂度是O(1)，因为不需要移动元素。但如果你在切片中间或开头插入元素，那么时间复杂度将是O(n)，因为需要移动元素。

需要注意的是，Go语言的切片在底层数组容量不足时会自动扩容，扩容操作涉及到创建一个新的、更大的底层数组并将旧数组中的元素复制到新数组中，这个操作的时间复杂度是O(n)。但是，由于扩容不是每次插入操作都会发生，且扩容策略（通常是容量翻倍）使得扩容操作的平均时间复杂度可以被摊销到O(1)，因此从平均情况来看，切片的插入操作可以被认为是O(1)时间复杂度。然而，在最坏情况下（即每次插入都导致扩容），时间复杂度将是O(n)。
